# 宿主卡顿与拖动复查（2026-11-17）

> 早期开发诊断记录，非 v0.1.0 的受控性能基准。后续拖动已改用捕获输入事件结束手势，当前行为以源码与组件说明为准。

## 事实与验证范围

用户报告点击卡顿、拖动再次失效。新 `weather-card` 当时尚未加载进常驻实例，不能把当时的开销归因于新 Canvas 引擎。

原常驻实例短时采样中，宿主约占一个 CPU 核心的 69.3%，最高 WebView2 子进程约 67.7%；三秒内私有内存基本持平。修复并重新加载后的一次五秒样本中，宿主约 34.8%，最高 WebView2 子进程约 6.6%。这里是单核时间占比，不是整机 CPU 百分比。各阶段有启动缓存、用户缩放及布局变化，数据是诊断样本，不能当作严格受控基准，也不能证明或排除长期内存泄漏。

## 修复

1. 原 `WM_WINDOWPOSCHANGING` 处理不区分调用者的 `SWP_NOZORDER`，会把本来不要求重排的通知改成沉底。已保留原始 Z-order 语义，只在初始显示、固定层级切换或桌面关联变化时显式定位。仍保留桌面 owner、隐藏/最小化保护与不激活样式。回归用实际消息及原生 WINDOWPOS 内存复现了原错误。
2. 原热重载只证明文档重新加载，没有证明 ES Module 新内容生效。隔离副本中修改 `app.js` 后，原实现会重启文档但仍执行旧模块。现在初始导航和重载前只清理当前 profile 的 DiskCache，保留 localStorage/cookie；回归检查实际新模块标记已执行。窗口关闭与应用退出等待初始化和异步重载完成。
3. 内置 PNG 背景不再与会持续运行的 SVG 回退同时加载；仅当 PNG 加载失败时启用 SVG。时钟和黄历不再持续移动装饰薄雾，天气云层以约 20 个离散步骤/秒慢速移动。不透明内置底图下移除没有视觉贡献的根级 backdrop blur，纯玻璃模式保留。
4. WebView2 合成画面捕获设置为三分频，减少纹理复制。当前固定 SDK 1.0.4314.35 仅内部暴露已注册的 `FpsDividerProperty`；兼容处理只取得该依赖属性并用 WPF SetValue 设置，测试验证值为 3。升级 SDK 需重新验证，公开分频接口可用后应删除此兼容查询。
5. 拖拽启动与虚框跟踪使用较高调度优先级，避免 Background 计时器被画面捕获挤压。全应用同时只保留一个拖动会话，新手势取消旧会话；按当前主鼠标键映射判断释放，过期按下坐标不再复用。松手只移动真实窗口一次，锁定/关闭/取消会释放虚框和计时器。
6. 关闭时从可视树与名称域移除已释放浏览器，清除初始化任务持有的图形对象引用；退出前在 STA 仍能泵消息时回收已关闭的 WinRT 图形对象，然后关闭应用持有的合成队列。

## 回归证据

`tests/host-smoke.ps1` 使用独占临时目录与独立浏览器数据目录，覆盖：

- 七个插件发现与新旧清单尺寸兼容。
- 每实例 origin/profile/localStorage 隔离。
- 所有原组件的网页拖动消息与统一宿主拖拽柄。
- 只移动虚框、松手一次移动、取消、锁定、会话互斥。
- 45 次虚框会话循环后没有活动拖动，USER 资源计数保持有界。
- NOZORDER、捕获分频、真正更新模块内容的热重载。
- 旧天气、时钟、黄历与新 Weather Card 的布局、数据和渲染检查。
- 配置恢复与进程正常退出。

尚未完成长时间驻留泄漏测试、真实鼠标跨屏压力测试及不同显卡/DPI/Explorer 版本的覆盖。自动回归通过不等于用户已经确认点击手感或所有桌面行为。
